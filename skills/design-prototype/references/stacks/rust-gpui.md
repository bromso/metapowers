# Rust and GPUI

Written against `bromso/boilerplate-rust` at `232dc095188c8d4dbe8db291106132ce2f2d9b54` (main) on 2026-10-30. Refresh this file from that repository's `main`, never the other way round.

A Rust workspace (edition 2024, resolver 3, toolchain pinned to 1.97.1 with rustfmt, clippy and the `wasm32-unknown-unknown` target) in a hexagonal layout: wasm-clean `domain` (`crates/core`) and `api-types` crates, Axum 0.8 HTTP apps, Turso 0.8 (SQLite-compatible) through `db`, Askama templates, a GPUI 0.2 desktop app, Tokio, `jiff` for dates, Argon2 for passwords, `clap` CLIs. Tests run with `cargo nextest`, `insta` snapshots, `proptest` and `rstest`; `cargo-deny`, `cargo-machete`, `cargo-hakari` and `taplo` keep the workspace honest; `just` wraps the commands and `cargo xtask` runs CI.

## Commands

| When | Command |
| --- | --- |
| Install the toolchain and tools | `rustup toolchain install` (reads `rust-toolchain.toml`), then `cargo install --locked cargo-nextest cargo-hakari cargo-deny cargo-machete taplo-cli` |
| Build every crate | `just build` (`cargo build --workspace`) |
| Run all tests | `just test` (`cargo nextest run --workspace`) |
| Lint: fmt, clippy, taplo, machete | `just lint` (`cargo xtask lint-all`) |
| Format | `cargo fmt --all` (checked by `just lint`) |
| Prove the wasm-clean crates still build for wasm | `just check-wasm` |
| Licenses, advisories, bans, sources | `just deny` (`cargo deny check`) |
| Regenerate the workspace-hack crate after dependency changes | `just hakari` |
| Rebuild the CSS (Tailwind standalone, pinned) | `just css` (watch: `just css-watch`) |
| Everything CI runs, before a commit or before claiming done | `just ci` (`cargo xtask ci`: fmt check, clippy, machete, tests) |
| Run the platform (API on 127.0.0.1:3000) | `just run-platform` (`cargo run -p platform`) |
| Run the CLI | `just run-cli <args>` (`cargo run -p cli -- …`) |
| Open the desktop window | `just run-desktop` (`cargo run -p desktop`) |

Use the `just` recipes; a bare `cargo test` is not the test command (nextest is), and `cargo clippy` alone is not the lint (`xtask lint-all` adds fmt, taplo and machete). On Linux, GPUI needs system packages (`libxkbcommon-x11-dev libwayland-dev libfontconfig-dev libfreetype-dev libx11-xcb-dev libxcb1-dev libvulkan-dev clang cmake`), as CI installs them.

## Layout

```
crates/          api-client, api-types, auth, auth-http, config, core (package `domain`), db, i18n, jobs, mail, password, realtime, service-kit, sites, tokens, web, workspaces
apps/            account, api, app, auth (package `auth-app`), cli, desktop (GPUI), gallery, platform
xtask/           cargo xtask <ci|lint-all|release|css>
workspace-hack/  generated by cargo-hakari
docs/            ROADMAP.md and design notes
Cargo.toml (workspace, lints, [workspace.dependencies]), rust-toolchain.toml, justfile, clippy.toml, deny.toml, taplo.toml, .cargo/config.toml, .config/hakari.toml
```

- Integration tests live in `crates/<crate>/tests/*.rs` and `apps/<app>/tests/*.rs`; unit tests sit in the module they test; `insta` snapshots under `src/snapshots/*.snap`; shared test helpers in a crate's `src/testing.rs`.
- A new crate goes under `crates/` (library) or `apps/` (binary), is added to `[workspace.dependencies]` as a path entry, uses `{ workspace = true }` for every dependency, and gets a `README.md` stating what it must not depend on; then `just hakari`.

## Rules

- `domain` and `api-types` stay wasm-clean: no I/O, no tokio, no other workspace crates (`api-types` depends on no workspace crate).
- `auth` depends only on `domain`; `password` only on `auth`; `api` uses `auth` but never `db` or `password`.
- `db` depends only on `domain` among workspace crates and stays independent of `auth`; only `platform` wires `db`; `cli` and `desktop` never depend on `db`.
- `jobs` depends only on `db` and `domain`; `mail` only on `i18n`; only `platform` depends on both `jobs` and `mail`.
- `service-kit` depends only on `api-types`; `api` never opens the database and gets services through `ApiState`.
- `auth-http` depends only on `auth` and `service-kit`, never `web` or `db`; `web` depends only on `tokens`, `sites`, `i18n` and `service-kit`.
- `tokens`, `sites` and `i18n` depend on no workspace crate; `workspaces` only on `domain` and `auth`.
- All versions live in the root `[workspace.dependencies]`; members use `{ workspace = true }`.
- Workspace lints: `unsafe_code = "deny"`, `clippy::unwrap_used = "deny"`, `clippy::pedantic` warned, `missing_docs` warned.
- Each crate's `README.md` states what it must not depend on; a reviewer checks a change against that file.
- `just ci` passes before a change is called done.

## For skills

- **Build, test, lint, ship:** `just build`, `just test`, `just lint`, and `just ci` as the gate; `just deny` after a dependency change, `just hakari` after adding or removing one. Never a bare `cargo test` or `cargo clippy` in place of the recipes.
- **Review:** check the dependency rules above against the touched crate's README, that no `unwrap` or `unsafe` slipped in, that new dependencies went through `[workspace.dependencies]`, and that `just ci` passes.
- **Prototype or component generation:** desktop UI goes in `apps/desktop` on GPUI 0.2; HTTP handlers in the owning app under `apps/` with types in `api-types`; templates are Askama; a new binary is an `apps/<name>` crate with its own README.
