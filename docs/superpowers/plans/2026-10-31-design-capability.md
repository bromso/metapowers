# Design without a bundled server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The nine Figma-dependent design skills name capabilities instead of a removed server's tool names, bind them at run time to whatever Figma MCP server the user connected, state what they do without one, and record the binding in the artifact.

**Architecture:** One more generated Prerequisites paragraph (the Figma step) owned by `pack-tools fix-skill-text` and mirrored by the validator, triggered by `metadata.figma-aware: true`, placed after handoff, recall and stack. Two canonical reference files under `references/design/` (the capability contract and the server-free accessibility checks) bundled by `gen-references`. The skills' Process steps are rewritten by hand in one fixed two-path form (`*Figma (…):*` / `*Without Figma:*`); a validator rule forbids the old `figma_*` names from coming back. Docs get a Figma page.

**Tech Stack:** Bun 1.3 + Turborepo; TypeScript; Vitest 3; Biome (tabs, width 100). Skills are Markdown with YAML frontmatter.

**Spec:** `docs/superpowers/specs/2026-10-31-design-capability-design.md` (reads §8/§10 of `2026-10-26-singularskills-foundation-design.md` and §6–7 of `2026-10-30-stack-and-memory-design.md`).

## Global Constraints

- The only new frontmatter key is `metadata.figma-aware` (boolean), on exactly the nine skills of spec §2.
- No code talks to Figma; no `.mcp.json`; no network call in any skill or script (spec §3).
- The Figma step is generated by `fix-skill-text`, mirrored by the validator, checked by `check:pack`; skill prose is rewritten only where spec §5 says (spec §9).
- Order inside `## Prerequisites`: handoff, recall, stack, figma, gate-or-started step, then the skill's own prose (spec §6).
- A design skill links its domain references without the domain segment: `references/figma-capabilities.md`, `references/a11y-checks.md` (spec §4).
- No skill body may contain an identifier matching `\bfig(ma|jam)_[a-z_]+` (spec §8).
- `bun run lint:skills`, `bun run check:pack`, `cd apps/docs && bun run check`, `bun run evals --dry`, `SKIP_NETWORK_TESTS=1 bun run test`, `bun run check` (Biome) and `bash scripts/check-rename.sh` stay green at every commit (spec §9).
- Conventional commits ending with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Working tree: the worktree `.claude/worktrees/site-storytelling`, branch `design-capability`. Run `bun run build` in `packages/pack-tools` before using its CLI.

## Review Focus

1. A no-server run must never ask for a Figma link: pinned by the step's exact text (Task 2) and by acceptance 3 (Task 7, `design-system-overview` with no server).
2. Values the user supplied (a brief, a token file) must be used, not marked `not checked`: pinned by the contract's "What counts as read" section (Task 1) and the `design-empathize` dry eval staying listed (Task 7).
3. A later phase must read the file link from the earlier artifact's `## Tools` before asking: pinned by the step text (Task 2) and the test skill's step 1 (Task 3).
4. `generate_figma_design` and `use_figma` must not trip the tool-name rule while `figma_get_variables` and `figjam_create_stickies` must: pinned by Task 5's tests.
5. `review-deck.md` must pass the gate hook and be listed by `singular-status` as a utility artifact, not as unmatched: pinned by Task 4 (status wording) and acceptance 3 (Task 7).
