## Purpose

The accessibility audit utility runs a full WCAG accessibility pass over a Figma component or frame in one go: design lint, color contrast, color-blindness simulation, and focus order. Use it when you want a quick accessibility check on a Figma design before it goes to development.

See also `/accessibility:scope` for the full audit path — target, WCAG level, and test plan — rather than a one-pass Figma check.

## Usage

```
/design:a11y-audit
```

Point at a Figma component or frame (by name, node ID, or current selection) and the skill runs the checks against it.

## What It Does

1. Identifies the target component or frame
2. Runs `figma_a11y_lint` to check text size, touch targets, and image alt text
3. Runs `figma_a11y_scorecard` for an overall accessibility scorecard
4. Runs `figma_a11y_focus_order` to validate tab order
5. Checks color contrast with `figma_a11y_contrast_check` for each foreground/background pair, at both normal and large text sizes
6. Simulates color blindness (protanopia, deuteranopia, tritanopia) with `figma_a11y_color_blind_sim` for the primary color pairs
7. Compiles and presents the audit report

## Output

A comprehensive accessibility audit report presented to the user, covering:

- Summary of checks run and pass/fail counts
- Lint issues (text too small, touch targets, missing alt text)
- Contrast results (AA/AAA pass/fail per pair)
- Color blindness results
- Focus order analysis
- Remediation recommendations

## MCP Tools Used

- `figma_a11y_lint` — Lint a Figma component for accessibility violations
- `figma_a11y_scorecard` — Generate an overall accessibility scorecard
- `figma_a11y_contrast_check` — Check color contrast ratios against WCAG thresholds
- `figma_a11y_color_blind_sim` — Simulate color-blind views of a component
- `figma_a11y_focus_order` — Validate keyboard focus order annotations

## Next Phase

After the audit, proceed to [Design Review](/docs/design/design-review) to check the component against the rest of the system.
