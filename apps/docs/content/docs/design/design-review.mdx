## Purpose

The design review utility writes a deck that summarizes a component's full design journey (research, definition, ideation, prototyping and testing) as `review-deck.md` in the project folder, and publishes it to Figma Slides when you give a deck link and a server is bound. Use it when you need to present a component's design work to stakeholders or walk a team through it.

Not for feedback on a design in progress — see `/coaching-ux` or `/design-test`.

## Usage

**Example:**
```
/design-design-review button
```

Give a `figma.com/slides/` link in the request to publish the deck to Figma Slides as well.

## Prerequisites

At least the Define phase (`.singularskills/design/<project>/02-define.md`) should exist. More completed phases produce a richer presentation.

## What It Does

<Steps>
<Step>Reads all available phase artifacts for the project (empathize, define, ideate, prototype, test)</Step>
<Step>Writes `review-deck.md`: a title slide, one slide per completed phase with its key findings, and a summary slide with status, decisions and next steps</Step>
<Step>Publishes to Figma Slides when a deck link is given and *Figma* is bound, with a screenshot of the prototype on its slide</Step>
<Step>Presents the deck path, the slide count and the Slides link when published</Step>
</Steps>

## Output

<Output>
`.singularskills/design/<project>/review-deck.md` (a utility artifact: `phase: null`, `gate: none`, with Decisions and Open questions), and a Figma Slides deck when published.
</Output>
