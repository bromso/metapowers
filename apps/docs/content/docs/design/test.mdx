## Purpose

The test phase validates the completed prototype against the component contract and WCAG accessibility criteria, producing a pass/fail report.

## Prerequisites

All prior phase artifacts should exist in `.metapowers/design/<component-name>/`.

## What It Does

<Steps>
<Step>Reads the component contract and prototype notes</Step>
<Step>Checks each contract requirement against the prototype</Step>
<Step>Runs `figma_a11y_lint` to detect accessibility issues in the Figma component</Step>
<Step>Generates a scorecard with `figma_a11y_scorecard` for overall a11y health</Step>
<Step>Validates contrast ratios with `figma_a11y_contrast_check`</Step>
<Step>Simulates color-blind views with `figma_a11y_color_blind_sim`</Step>
<Step>Checks focus order with `figma_a11y_focus_order`</Step>
<Step>Generates a test report with pass/fail for each criterion</Step>
<Step>Writes to `.metapowers/design/<component-name>/test-report.md`</Step>
</Steps>

## Output

<Output>
Creates `.metapowers/design/<component-name>/test-report.md` containing:

- Contract compliance checklist (pass/fail per requirement)
- WCAG validation results
- Issues found and remediation suggestions
- Overall pass/fail status
</Output>

## After Testing

If the test report identifies issues, iterate by returning to the relevant phase (often prototype or define) to address them. The artifact flow is designed for iteration — update the artifact and re-run downstream phases.
